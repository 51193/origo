## 事实与目标

调查日期2026-09-18，基线`cdba5e4`；本文提出方案，不改变当前规则。独立读取文件和运行 `python scripts/validate-agent-docs.py` 均确认：根 `AGENTS.md` 为223行、16364字节。守卫设 `MAX_LINES = 300`、`MAX_BYTES = 16 * 1024`，因此字节余量20。守卫还要求11个固定小节标题及命令、关键字；精简时只改正文会受这些结构约束。

这不是Codex自身的16 KiB限制。[官方 AGENTS 文档](https://developers.openai.com/codex/guides/agents-md/) 说明指令沿仓库根至当前工作目录合并，默认项目指令总预算32 KiB。子目录指令不是按“正在修改的文件”自动遍历加载：从仓库根启动时，不能假设嵌套文件会生效。

**推断：** 当前入口容量接近本地门禁，适合重组；但223行本身不能证明质量差。优化以任务定位正确率、约束遵守和读取成本为准，100行不是验收标准。

## 常驻约束与按需过程

全局约束必须保留明确可执行的含义：

- 单一权威入口、用户语言、任务范围与权限；冲突在同次变更修正。
- 源码前读模块文档、上下游和相关设施；改文件前读历史。不能为提效把full-chain缩成“只读当前文件”。
- fail-fast与严格完整性；策略状态、生命周期和Core/Adapter边界的权威入口。
- 单一访问路径；不得手拼低层调用绕过钩子、校验和资源生命周期；可疑后门须确认设计。
- 早期开发的干净破坏性变更；禁止兼容壳与测试便利接口。
- 双语DocSync、禁止手改生成物、公共XML英文注释、禁止DocFX/Sandcastle。
- `global.json`权威与正确引导入口；不得降级SDK或用临时环境覆盖替代。
- 完成定义：测试、Changelog对齐、文档同步、提交及提交后完整CI/消息lint按规定闭环；未完工作进入缓冲。

依赖家族的完整解释、发布元数据清单、DocSync操作细节、测试内部访问白名单、缓冲producer/consumer记录字段，可移到权威文档或任务skill。根仍保留触发条件和必需门禁。不是删除约束，而是把“何时必须读取什么”写清楚。

## 路由矩阵提案

| 任务触发 | 起始材料 | 必须扩展的链 | 验证证据 |
|---|---|---|---|
| 只读研究/评估 | 架构与任务相关文档 | 结论涉及的模块契约；必要时源码 | 来源、基线、事实/推断/未知项；不要求凭空修改生产测试 |
| 文档内容改动 | META完整权威；相关模块 | 引用的使用/接口/测试文档 | 双语、generate/validate及现有闭环；不制造无行为价值的测试 |
| Core缺陷 | 目标模块；META；测试规则 | 上游输入、下游消费者、同类路径、文件历史 | 真实路径红→绿、兄弟路径；开发与最终门禁 |
| 公共API/文件结构变化 | 目标及相关模块；API消费方 | public白名单、接口边界、镜像清单 | 行为测试、BREAKING判断、接口/文件清单、DocSync |
| Godot运行/输入问题 | Adapter、宿主、Console、集成测试资料 | Core帧边界、节点、真实输入消费 | 最新构建；headless与GUI适用性；状态和画面证据 |
| 依赖更新 | 引导与Dependabot说明 | 版本耦合、生成器/SDK/测试运行器 | 同家族更新和全量门禁；不得单独升级成员 |
| 正式发布 | release-process完整权威 | version/analyzer/release workflow/docs | verify-release、生成物、提交后CI/lint、tag步骤 |
| 发现未完事项/恢复任务 | META缓冲完整协议；缓冲根与相关章节 | 基线复核、关联设施、历史/命令 | ownership、状态、失败、下一动作、最终提交 |

这是待实施的路由，不是本次授权豁免。当前AGENTS的完整读取和闭环仍适用。尤其当前 §0 要求完整release-process；若采用按发布任务读取，必须同步修改AGENTS、两侧META、release-process和指令守卫，不能让skill自行覆盖。

Changelog的一般分类和BREAKING判断与正式发布操作要分开路由；普通源码改动仍可能需要读取Changelog规则。META也不能简单整份变成“可选”：文档写入、构建和缓冲动作各有必须读取的权威章节。可以保留META完整权威正文，通过独立的任务入口准确指向章节，减少重复摘要。

## 一个路由实例

任务：“修正 `entity_set_data` 命令对已有float键的写入行为”。起点应为 [Console](../../Origo.Core/Runtime/Console/README.zh.md)、其CommandHandlers文档和 [命令语义](../../usage/console-commands.zh.md)，然后读数据类型与转换器协作者、真实命令队列/帧驱动、相关测试和历史。不能只改数字解析函数而忽略保留已有类型的契约。

根入口应告诉Agent如何找到这条链；路线中的命令测试skill应提示经真实队列和帧入口复现。完整正式发布清单不帮助这项诊断；公共API变化、Changelog和最终CI却仍可能适用。受影响检查只缩短迭代，不代替完成门禁。

## 如何落地和验收

先列“规则→常驻/路由→唯一权威→检查”的清单，逐条迁移，检查没有删掉含义或产生双重来源。更新守卫时保留预算、路径、关键门禁和禁止事项检查；把固定章节编号守卫转成规则覆盖检查需要专门验证，不能直接移除保护。

验证应同时覆盖仓库根启动、子目录启动、显式skill、无skill支持的Agent，以及中途出现存档/Godot范围扩展。用同任务、同基线、同模型预算对照；记录遗漏协作者、违规次数、达到正确检查前的读取量和耗时。若更短却漏读关键文档，方案失败。若常驻内容下降但skills目录膨胀导致总体读取更多，也需修正。

最终交付物应包含根入口、任务矩阵、可直接读取的权威链接、守卫调整、迁移完整性表和A/B结果。当前报告仅定义这些产物，未实施、未给出成绩。
