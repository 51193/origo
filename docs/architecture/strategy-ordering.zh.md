# 生命周期策略的顺序约束

> [↑ 回到 architecture](README.zh.md)

生命周期策略使用 Before / After 相对顺序约束。顺序约束只约束同一实体的生命周期策略，不要求被引用策略挂载；主动、观察者和状态机策略沿用各自调度契约。选择单一相对顺序模型，使先后意图直接表达，避免数字排序与关系排序产生两套相互冲突的语义。

顺序约束在完整注册表中成立，实体顺序保留传递关系：A 先于 B、B 先于 C 时，只挂载 A 与 C 的实体仍须先执行 A。没有约束的候选策略按索引的 Ordinal 顺序选择，以消除注册、挂载与恢复输入顺序造成的差异。Process 和批量生命周期钩子使用同向顺序，清理钩子不自动逆序：顺序约束表达的是依赖方向，而不是资源栈的获取/释放关系；保持各批量阶段同向可避免同一策略在不同钩子间出现两套顺序语义，也使存档、恢复与退出清理使用同一确定性顺序。

顺序关系只声明在策略类型特性上，不提供每实体覆盖：每实体覆盖要求把约束写入存档并在恢复时重建逐实体约束图，复杂度与失配风险显著高于当前收益。注册限于启动阶段；自动发现完成后（直接使用 SndWorld 时，在首次生命周期策略实体创建前）校验引用与环并固定注册表，固定后注册操作明确失败。约束中的未知索引、非生命周期策略、自引用和环均明确失败；环诊断给出实际路径。存档仅记录挂载索引，恢复时使用同一注册关系。固定关系避免运行期新增策略改变所有实体的排序。

## 已知边界与演进选项

### 完整注册图包含未挂载策略

当前行为：`SealRegistration()` 在完整注册表上校验 `Before` / `After`，目标策略必须已注册；目标不必挂载，但缺少目标会让启动失败，即使声明约束的策略从未被任何实体挂载。

原因：一次校验并冻结可为所有实体提供同一确定性顺序；支持前向引用；实体恢复不需要逐实体建图。

已知问题：
- 可选策略包形成启动期耦合：插件 A 引用插件 B 的索引时，未加载 B 会让整个游戏启动失败，即使 A 从未挂载。
- 失败发生在注册阶段，距离“哪个实体真正需要该关系”较远，诊断成本高。
- 移除可选插件必须同时移除或改写引用它的约束。

快速演进选项：
- 可选目标：为约束目标增加显式可选语义或独立的目标解析策略；目标缺失时必须有确定且可观察的降级规则，禁止静默忽略。
- 按实体闭包校验：注册阶段只记录声明；实体恢复/挂载时只对实际挂载集合的传递闭包做校验与排序；存档格式可不变，但需要逐实体图与缓存。
- 作用域约束：约束目标限定在同一插件/命名空间作用域，跨作用域引用必须显式声明。
- 保持现状并补诊断：注册失败时说明涉及的策略、边和可能受影响的实体，并在 analyzer/文档中提示可选依赖风险。

重新评估信号：出现可选策略包或第三方扩展的约束耦合问题，且无法通过调整注册集合或声明关系解决。

### 全局拓扑秩投影与 Ordinal 语义

当前行为：完整注册表经 Kahn 拓扑排序得到全局全序，候选按 `StringComparer.Ordinal` 取最小；实体顺序是该全序在已挂载集合上的限制。`Before` / `After` 的直接与传递约束在所有实体上一致保留。

已知问题：
- “无约束策略按 Ordinal”只描述全局候选选择，不保证任意两个在偏序中不可比较的已挂载策略在所有实体上仍保持 Ordinal。
- 只要某条约束涉及已注册但未挂载的策略，就可能改变两个已挂载策略的相对顺序；新增或删除无关注册也可能改变实体顺序。
- 因此实体顺序不能理解为“局部插入顺序 + 局部约束”，而是全局冻结顺序的投影。

快速演进选项：
- 逐实体约束投影：实体恢复时对实际挂载集合重放完整偏序约束（含传递闭包），再做稳定拓扑排序；必须额外定义不可比较节点的排序目标（例如最小化相对 Ordinal 的逆序）。
- 实体级顺序配置：在实体元数据中持久化显式顺序覆盖或分组；代价是存档格式、恢复与校验复杂度上升。
- 保持全局全序：明确 Ordinal 只是全局候选 tie-break；顺序敏感实体必须显式声明约束，不依赖投影偶然性。

重新评估信号：无法用显式约束稳定表达的顺序需求反复出现，或实体级顺序审计发现投影结果与团队预期系统性不符。
